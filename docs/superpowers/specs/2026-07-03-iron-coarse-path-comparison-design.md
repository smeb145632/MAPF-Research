# Iron Coarse Path Comparison Design

## Purpose

Extend the existing `iron_regions_v7.html` prototype into a visual verifier for
two approximate distance estimators:

1. global A* on the 16×16 coarse grid;
2. hierarchical Region/Portal search with cached intra-region portal distances.

The prototype remains a browser-only validation tool. It does not change the
C++ planner or claim exact original-grid shortest paths.

## Existing Baseline

The page is generated by:

`benchmark_results/iron_region_graph/render_iron_regions.py`

It already embeds:

- the original Iron obstacle map;
- 16×16 coarse-cell passability;
- Region assignments;
- virtual separators;
- ordinary, adjacency, diagonal, and blocked-connector Portals;
- interactive source and target selection.

The generated validation page remains:

`benchmark_results/iron_region_graph/iron_regions_v7.html`

## Interaction

- Ctrl+click selects the source.
- Shift+click selects the target.
- Both algorithms run automatically after both endpoints exist.
- A clear button removes endpoints and both routes.
- Existing pan, zoom, hover, Region selection, and layer toggles remain usable.

## Algorithm A: Global Coarse A*

### State

One state per passable coarse cell. No orientation is stored.

### Edges

Four-neighbor cardinal movement between passable coarse cells. Each edge costs
one coarse step.

Approximate map-scale distance is:

`endpoint attachment cost + coarse steps × BLOCK`

The endpoint attachment cost measures the source/target position to the center
of its resolved coarse cell. Endpoints in approximate-obstacle cells use the
existing original-grid binding logic to attach to reachable Regions or connector
Portals.

### Heuristic

Coarse-grid Manhattan distance. Because edge costs are uniform and movement is
cardinal, this is suitable for the coarse A* baseline.

### Output

- reconstructed coarse-cell polyline;
- approximate path length;
- expanded-state count;
- runtime;
- failure reason when no route exists.

## Algorithm B: Hierarchical Region/Portal Search

### Graph State

The search state is:

`(portal index, current Region id)`

Keeping the Region side is required because the same Portal can be entered from
different Regions.

### Transitions

1. Cross a Portal into another Region touched by that Portal.
2. Move within the current Region from the current Portal to another Portal.

Crossing a Portal has a small fixed coarse cost. Intra-region movement uses
coarse A* restricted to that Region.

### Endpoint Attachment

Resolve source and target into one or more Region bindings. Rank Portals in each
endpoint Region and retain the nearest four reachable candidates.

Endpoint-to-Portal distances are computed with Region-restricted coarse A*.

### Cache

Cache intra-region distances using:

`(Region id, min Portal id, max Portal id)`

Each entry stores distance and, when requested for display, the reconstructed
coarse-cell segment. Repeated queries reuse these entries.

The result panel reports cache hits and misses for the current query and total
cache size.

### Output

- a polyline assembled from endpoint and cached Portal segments;
- approximate path length;
- high-level expanded-state count;
- coarse A* expansions used by cache misses;
- Portal count;
- cache hits, misses, and total entries;
- runtime or failure reason.

## Path Rendering

The two estimators remain visually distinct without obscuring the map:

- Global coarse A*: cyan-blue, thinner, slightly transparent.
- Region/Portal path: warm amber, thicker, solid.
- Shared source: green marker.
- Shared target: rose marker.
- Used Portals: amber rings with a light center.

Both paths receive a dark under-stroke so they remain legible over all Region
colors. The active route can be emphasized from the result cards, but both are
shown by default.

## Result Panel

Use two compact comparison cards:

| Card | Main value | Secondary values |
| --- | --- | --- |
| Global coarse A* | estimated length | expansions, runtime |
| Region/Portal | estimated length | portals, expansions, cache |

A small comparison row shows absolute and percentage distance difference.
Failure appears inside the affected card and does not break the other method.

The panel must remain compact, use the existing dark visual language, and avoid
covering the central map viewport.

## Error Handling

- Invalid or obstacle endpoints use the existing endpoint resolver.
- If an endpoint cannot bind to any Region, show a local error.
- If global coarse A* fails, the hierarchical query may still render.
- If hierarchical search fails, global coarse A* remains visible.
- Missing Portal connectivity is reported rather than replaced silently by a
  direct line.
- Search expansion limits prevent the browser from freezing.

## Validation

Test at least:

1. source and target in the same Region;
2. source and target in distant Regions;
3. an endpoint in a blocked-connector coarse cell;
4. a path using a diagonal Portal;
5. disconnected or invalid endpoints;
6. repeated query demonstrating cache hits;
7. pan, zoom, hover, and layer toggles after routes are drawn;
8. page layout at common desktop viewport sizes.

Success means both paths render independently, metrics update correctly, cached
queries reduce repeated coarse searches, and the page remains readable.
